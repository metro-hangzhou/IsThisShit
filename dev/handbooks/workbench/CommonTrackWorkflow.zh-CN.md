# 共轨工作流

状态：`draft_round_002`

## 作用

定义一套共享 workflow，用来：

- 读取旧系统
- 重设计
- 审阅
- 修正
- 放行

它未来将被用于治理仓库各子系统的重构和开发。

## 核心角色

- `explorer`
  - 提取事实、结构、冲突、耦合点
- `worker`
  - 产出重构草案，并响应 reviewer blocker
- `reviewer`
  - 做严格结构化批判，给出 pass/fail blocker
- `main agent`
  - 负责编排轮次、下发任务、整合结果、做验收与总测试
- `user`
  - 在预设 gate 节点做人工放行

## 强制原则

- 先归档后改写
- 在实质工作前先完成文档式强路由
- 默认采用 `subagents-first` 的执行方式
- 默认下发模型为 `gpt-5.5`
- 默认下发推理强度为 `xhigh`
- main agent 主要负责派单、验收与总测试
- 所有单元都必须遵守第一性原理法
- workflow 内部沟通默认保持扁平化并通过文件系统留痕
- 当 evidence 已足够定论时，证据优先决策必须压过无意义 timeout 或路径膨胀
- 当更短、更正确、更低成本的路径已经在当前规则体系中可见时，不允许停在“够用版”“过渡版”“差不多版”
- reviewer 输出必须结构化
- worker 响应必须显式存在
- phase 切换必须经过用户闸门
- 不允许静默从 draft 升成 canonical
- 出口性产物必须携带 “实现状态说明/占位警告块”，说明哪些特性依然处于占位、启发式、采样或未完工状态，不能直接标记“完成”或“最终”，确保任何 downstream reviewer/用户都知道此处貌似可靠其实还在修。
